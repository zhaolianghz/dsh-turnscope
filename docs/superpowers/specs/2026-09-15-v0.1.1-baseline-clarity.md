# V0.1.1 — Baseline-Dirty Clarity

## What the user reported

In a DSH session whose worktree was dirty when the session opened, every turn shows the same large number in **变更文件 (Changed files)** — the 76 paths that were already modified before turn 1 even began. The per-file detail view does label each one as `本轮开始时已脏 (Dirty when the turn started)`, but the summary count lumps them together with the agent's actual changes, so the headline number is misleading.

The user expects: **the headline count should reflect what the agent did this turn**, not the noise of state it inherited from the worktree.

## Root cause

`host/query/service.ts` builds the per-turn `changeCount` from `result.changeSet?.changes.length`, which is the length of every `FileChange` — including rows with `attribution: 'AGENT'` *and* rows with `baseline: true` *and* rows the agent did not touch (`attribution: 'BASELINE'` is not a value; see below). The renderer shows the total without distinguishing.

The `FileChange` type already carries two pieces of information that together answer the question:

| Field | Meaning today |
|---|---|
| `kind: 'modified' \| 'added' \| 'deleted' \| 'renamed'` | What the file did across PRE/POST |
| `baseline: boolean` | `True` iff the file was already dirty when the turn started |

What is missing is a count that says **"files the agent actually changed this turn"**, which is `(change.kind !== 'noop') && !change.baseline`.

(The DSH conversation turns labelled "Turn 2/失败" and "Turn 1/失败" with `Context / Context / Context` are a separate issue: those turns were already terminal when turnscope first saw them, so `inspector.observe()` returned without taking a `PRE`/`POST` capture, and the verdict column shows `证据缺失`. That is documented behaviour — V0.1 explicitly refuses to make safety claims about turns it did not watch — and it is fixed by restarting DSH with the plugin loaded at session start, not by a code change. It is not in scope.)

## Goal

Replace the misleading **变更文件** headline count with a count that reflects the agent's actual edits for the turn, and surface the baseline-dirty count separately so the reader knows it is inherited state.

In scope:
- The numeric headline on each turn card.
- A one-liner noting the baseline-dirty count when it is non-zero.

Out of scope:
- A new "session-start baseline" checkpoint (a deeper change to the inspector and storage; planned for a later minor release).
- The `证据缺失` columns (already correct).
- Per-file display (already correct).

## Design

### Wire-shape change (API_VERSION=4, additive)

Add two fields to `TurnSummaryDto` (`src/shared/contracts/api.ts`):

```ts
readonly agentChangeCount: number   // files the agent modified/added/deleted/renamed this turn
readonly baselineChangeCount: number // files that were dirty before the turn and stayed dirty through it
```

The existing `changeCount` becomes the sum of the two. Keep it as-is for backward compatibility (callers, tests, the renderer that already reads it for some layout calculations).

### Server side (`host/query/service.ts`)

In `summarize(...)`, compute the two counts from `result.changeSet?.changes`:

```ts
const changes = result.changeSet?.changes ?? []
const agentChangeCount = changes.filter(c => c.kind !== 'noop' && !c.baseline).length
const baselineChangeCount = changes.filter(c => c.kind !== 'noop' && c.baseline).length
const changeCount = agentChangeCount + baselineChangeCount
```

`evaluateSafety(...)` already returns `changeCount`. Mirror the split there too: add `agentChangeCount` / `baselineChangeCount` to `EvaluateSafetyData` so the renderer has both numbers in the same payload.

### Renderer (`client/TurnscopeView.tsx`, `client/TurnDetail.tsx`, `client/locales.ts`)

**Turn card** (the "Turn N / 变更文件 N" header):

- Show `agentChangeCount` as the number.
- When `baselineChangeCount > 0`, append a muted `+ N 本轮开始时已脏` chip next to it.
- When both are zero, the row shows `0` (unchanged).

**Turn detail header** (the count summary `dl` already in `TurnDetail.tsx`):

- Show `agentChangeCount` in the **变更文件** cell.
- When `baselineChangeCount > 0`, add a `Baseline dirty` row beneath it.

Add three locale keys per language (zh + en):

- `summary.agentChanges`: `本轮改动` / `Changed this turn`
- `summary.baselineChanges`: `本轮开始时已脏` / `Already dirty at turn start`
- `summary.baselineChangesShort`: `+{count} 已脏` / `+{count} dirty`

### Tests

- `tests/host/query/service.spec.ts`: extend existing service tests to assert both counts are computed and that the baseline row does not inflate the headline.
- `tests/client/recovery-section.client.spec.tsx` (or a new `tests/client/turn-card.client.spec.tsx`): assert the chip appears when `baselineChangeCount > 0` and is absent when it is zero.

### Architecture-guard reminder

The two numbers come from `FileChange` rows the inspector already produces. There is no new boundary to cross, no new IO, no new LLM, no telemetry. The existing `tests/host/architecture.spec.ts` raw-bytes allowlist does not need to change because no new module touches the worktree.

## Risk

- API_VERSION bumps to 4. The remote surface gains two optional fields; old clients ignore them. This is an additive strict-version bump per `docs/ARCHITECTURE.md` §5.
- The chip uses the `data-baseline` attribute on the existing `<dd>` element. Existing CSS that styles `data-baseline` (the `turnscope-baseline` class in `styles.ts`) already exists for the per-file row, so reuse the same class for the chip.

## What success looks like

After the patch:

- A turn with no edits shows **变更文件 0**.
- A turn with 3 edits and a 76-file dirty baseline shows **变更文件 3** with a muted `+76 本轮开始时已脏` chip.
- The per-file list still shows each path with its `本轮开始时已脏` badge, unchanged.
- `pnpm typecheck` clean, all tests pass.

## What this spec is not

It is not a redesign of the attribution pipeline. It is not a "session-start baseline snapshot" feature. It is a UI-correctness fix that uses information the host is already producing.
