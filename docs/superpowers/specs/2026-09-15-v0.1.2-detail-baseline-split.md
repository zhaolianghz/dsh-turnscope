# V0.1.2 — Detail-List Baseline Split

## What the user reported

After V0.1.1, the **headline** count on each turn card and detail header is
correct (agent edits + a muted `+N 已脏` chip when the worktree was dirty at
session start). The detail page itself, however, still lists every
`FileChange` row — agent edits and inherited baseline-dirty paths interleaved
in one flat `<ul>`. A reader who opens the detail to see what the agent did
this turn has to scroll past every inherited path.

The per-file `本轮开始时已脏` badge on each row is already there; the
remaining gap is that the list does not group these rows together.

## Out of scope

- **Bootstrap "Context/Context/Context" rows attributed to turn 1 / turn 2.**
  These are DSH session-startup conversation nodes that the assembler
  attributes to the first real turn because they have no `turn` of their
  own. Fixing this is a separate change in the assembler / turn grouping
  rules (`src/host/adapters/dsh/assembler.ts`), not a renderer change.
  Defer to a later release.
- **Status-label parity for `interrupted` / `cancelled`.** The client
  already surfaces host-recorded terminal states via a second chip
  (`status.hostSays` in `src/client/locales.ts` and `HOST_ONLY_STATUS_KEYS`
  in `src/client/keys.ts`), so the user does see "主进程记录：已中断".
  Collapsing that into a single badge would require unifying the
  client-derived `TurnStatus` (4 values) with the host's `TurnStatus` (7
  values), which is a wider change. Defer.
- **Evidence-missing explanatory text.** The current `证据缺失` label is
  terse; making it explain "plugin loaded after the turn started" is a
  separate UI polish.

## Goal

The detail page's change list splits into two visible groups when a turn
inherited dirty worktree state:

1. Agent edits — same markup as today, in the top list.
2. Inherited baseline-dirty paths — in a second list beneath a clearly
   labelled divider.

A turn with no baseline paths renders unchanged: one list, no divider.

## Design

### Renderer (`src/client/TurnDetail.tsx`)

Replace the single `detail.changes.map(...)` block with a grouped renderer:

```tsx
const agentChanges = detail.changes.filter(c => !c.baseline)
const baselineChanges = detail.changes.filter(c => c.baseline)
```

Then:

- If `baselineChanges.length === 0`: render the existing single `<ul>` of
  all changes (no behaviour change).
- Else: render the agent-changes `<ul>` first, then an `<h5>` (or `<p>`
  with the same `turnscope-section` class) reading
  `本轮开始时已脏 (N)`, then a second `<ul>` of baseline changes.

The per-row `本轮开始时已脏` badge (`TurnDetail.tsx:301`) stays — the
divider is the primary signal, the badge is the per-row confirmation.

### Tests

`tests/client/view.client.spec.tsx`: add one test that mounts a
`TurnscopeView` with a recorded turn whose change set has 3 agent edits and
5 baseline-dirty paths. Assert:

- The first `<ul>` contains exactly 3 path rows.
- The second `<ul>` (after the divider) contains exactly 5 path rows.
- The divider text contains `本轮开始时已脏 (5)`.

Add a second test with no baseline paths asserting only one `<ul>` renders.

No new locale keys (the divider text is a literal in the renderer; if we
later want it localizable, that's a follow-up).

## Risk

- Pure renderer change. No wire-shape change, no `API_VERSION` bump, no DB
  migration, no worktree write, no LLM call.
- The new code path is only taken when `baselineChanges.length > 0`; the
  default case (one list) is the existing implementation, byte-for-byte.

## Success criteria

- A turn with 3 agent edits + 5 baseline-dirty paths renders the 3 agent
  rows in the top list, then the `本轮开始时已脏 (5)` divider, then the 5
  baseline rows.
- A turn with 0 baseline-dirty paths renders the unchanged single-list
  layout.
- 593 tests + new tests pass; typecheck clean; client bundle size change
  < 1 kB.
