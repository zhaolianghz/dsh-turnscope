# dsh-turnscope V0.1：Turn Safety Inspector 开发计划

## Context

仓库当前在 `feat-prd-subagent-development` 分支上执行旧计划 `docs/superpowers/plans/2026-09-10-host-trace-core.md`（Task 1–5 已提交并 review clean，Task 6 未提交且 2 个断言待修）。新的两份 v0.2 文档把产品从「record-only trace」重新定义为：

> **证据采集 → 变化归属 → 安全判定 → 恢复决策**

这推翻了旧计划的三个前提：旧计划是"只记录、零动作"；v0.2 要求 attribution 与 Safety Verdict 成为产品核心；且 Checkpoint 必须保存 relevant path 的原始内容（否则 V0.2 逆向 patch / V0.3 worktree 重建在字节层面不可能正确）。

本轮目标（已确认）：**只做 PRD §15 / TECH §51 的 V0.1 Turn Safety Inspector**，即 TECH §61 的第一个里程碑——一个真实 Turn 走完 PRE/POST/CURRENT → 归属四态 → Safety 四态 → UI 展示原因。V0.1 **不做任何工作区写操作**（`docs/PRD.md` §15「明确不做」）。

已确认的四个方向（本次会话裁定）：

1. **范围**：只做 V0.1，不做 Rewind / Fork。
2. **代码策略**：保留已 review 的底座（storage / redaction / config / diagnostics / bundle），重写 domain + schema + adapter，目录重构为 `src/host|shared|client`。
3. **脱敏边界**：接受 v0.2 §12.3 / 决策 6 的反转——诊断负载继续脱敏，**recovery blob 原字节保存**，用 local-only + `0o600` + 保留期 + 永不上传来兜。
4. **RPC 通道**：先做 spike 验证第三方 remote 在 DSH 0.1.1-rc.2 是否可用，再定 UI 方案。

## 关键实测结论（决定方案形状）

- 本机装有真 DSH：`@deepseek-ai/dsh@0.1.1-rc.2`（`dsh` CLI），web profile 在 `~/.dsh/profiles/web`，bundles 为 `@deepseek-ai/dsh-base` + `@deepseek-ai/dsh-web-app` + `dshmarket`。`~/.dsh/turnscope` 已存在（此前被跑过）。**boot smoke 可做**。
- 第三方插件装法：`dsh plugin --profile <name> add <package>`（转发给 profile 目录里的 pnpm）。
- **Host↔Client RPC 对第三方插件未被证明**：第一方用 `@deepseek-ai/dsh-typert-protocol`（`TypertRemoteService` + `@Remote` 装饰器 + 生成的 `typert.host.js` / `typert.remote-client.js`）。但 `@deepseek-ai/dsh-api-remotes` 的 client 端是**闭集**，只装配 7 个第一方包的 remote（commands / file-reference / goal / host-plugin-inventory / message-feedback / session-reference / cordis-host-runner）。第三个新 namespace 能否被 client 调到，必须实测。
- 生成器 `@deepseek-ai/dsh-typert-generator` **未随包发布**，第三方要么手写那两个生成物，要么放弃 remote。
- 当前 client 是 **purely browser-side**：`src/client/TurnscopeView.tsx` 通过 `useSession(deriveTurnModels)` 直接投影 DSH 的 conversation snapshot，**完全不读我们的 SQLite**。所以 Safety/Attribution/Diff 需要一个全新的 Host API 通道。
- 现有 `vitest` 无配置文件，靠 `// @vitest-environment jsdom` 注释切换环境，测试目录布局可自由调整。

### Phase B — Domain / Schema / Storage v2

**B0. 处置在飞的 Task 6 代码**（当前工作树脏）
- 保留：`src/adapter/subscribe.ts`（`ctx.on('session/event')` 的接线方式已实证）、`src/adapter/normalize.ts`（事件→kind/phase 映射表可复用）。
- 重做：`src/adapter/assembler.ts` 按 v2 domain 重写（乱序缓冲 + 上限 + terminal 守卫的结构保留，记录形状与状态集改）。
- 重写 `tests/assembler.spec.ts` / `tests/trace-core.spec.ts` 中与实现自相矛盾的两个断言，而不是打补丁。
- 迁移到 `src/host/adapters/dsh/`，作为新计划的第一个提交，让基线干净。

**B1. Domain v2**（TECH §7）
- `NormalizedEvent` 增 `summary` + `source: {adapter, upstreamType}`；`ActivityKind` 增 `file`。
- `TurnStatus` 五态 → 七态（`+cancelled` `+output_limited`）；`TurnRecord` 改 `startedAt/endedAt` 为 ISO 字符串、增 `workspaceId` 与 `evidenceCompleteness`（`complete|partial|missing`）。
- 新增 `WorkspaceCheckpoint` + `CheckpointPathState` + `FileChange` + `TurnChangeSet` + `CommandEvidence` + `TestEvidence` + `FileToolHint`。
- ⚠️ 对文档类型的一处**有意扩展**：`FileChange` 增 `baseline: boolean`。§10.2/§10.3 需要"该文件在本轮开始前已脏"这一事实（黄金场景与 baseline 保留不变量都依赖它），但 §9.2 的 `FileChange` 没有承载字段。记录在代码注释里。
- `CheckpointPhase` 扩为 `pre|post|recovery_before|recovery_after`（后两态 V0.1 不写，先入类型与 DDL 以省一次迁移）。
- ids 保持确定性推导（`turnIdFor` / `activityIdFor` / `checkpointIdFor`），`SCHEMA_VERSION` 提升。

**B2. Schema 迁移 002**
- 新表：`checkpoint_paths`、`file_changes`、`commands`、`tests`、`safety_verdicts`。
- 改表：`workspaces`（`repo_identity` 取代 `repo_root_hash`）、`sessions`（去 `parent_session_id`）、`turns`、`activities`（`summary` 取代 `label`，去 `seq`/`truncated`）、`checkpoints`。
- 保留并复用现有 `application_id` 归属守卫、`user_version` 处理、`BEGIN IMMEDIATE` 迁移事务、STRICT 表。
- **必须写真实的 001→002 迁移路径**，不是重建库；`user_version` 高于本版本仍拒绝读取。
- 时间戳列类型：v0.2 记录用 ISO 字符串，DDL 用 `TEXT`（与旧 INTEGER 需迁移转换）。

**B3. Repository 端口 v2 + retention（吸收旧 Task 8）**
- 端口补 `deleteObject(ref)`、`putCheckpointPath` / `getCheckpointPaths`、`putFileChange` / `listFileChanges`、`putSafetyVerdict` / `getLatestVerdict`、`putCommand` / `putTest`。
- `src/host/storage/retention.ts`：纯函数 `selectEvictions(entries, limits)`，pinned 永不驱逐，确定性排序。
- 保留策略按 §45 分档：metadata 长、command payload 短、recovery blob 按容量、pinned 不自动清理。
- **`node:sqlite` 仍只允许出现在 `src/host/storage/`**（生产代码约束；测试可自行 import 以伪造外部库）。

**B4. 对象存储分两类（脱敏反转的落地）**
- `OBJECT_KINDS` 增 `RECOVERY_BLOB`（保留 `ACTIVITY_PAYLOAD`）。
- 把反转做成**显式、可审计**的，而不是静默放宽：`put(kind, bytes, { redaction: 'applied' | 'raw-bytes' })`；诊断路径必须传 `'applied'`，恢复路径传 `'raw-bytes'`。
- 用测试钉住：诊断路径永远传 `'applied'`；`'raw-bytes'` 只允许出现在 `src/host/git/` 下（架构守卫测试）。
- 新增守卫：`src/` 内不得出现任何网络调用（`fetch` / `node:http` / `undici`），兑现"永不上传"。

### Phase C — Workspace Observer（TECH §11 / §12）

**C1. CommandRunner + GitPort**
- `createExecFileRunner()`：仅 argv 数组、`shell: false`、非零退出**resolve** 而非 reject、`maxBuffer` 有界。
- GitPort 只读白名单：`rev-parse` / `status --porcelain=v2 -z` / `diff` / `diff --cached` / `ls-files` / `hash-object`（**不带 `-w`**）/ `cat-file` / `symbolic-ref`。
- 明令禁止：`reset --hard` / `clean -fd` / `checkout -- .`（用 grep 断言，见验收）。
- `-z` 解析按 `\0` 切分，rename 双路径形态要处理；非零退出返回 `undefined` 而非半成品值。
- 测试含**注入测试**：参数带 `; touch /tmp/pwned` 必须当作字面参数且不创建文件。

**C2. Repo identity（§11.2）**
- `rootIdentity = sha256(canonicalRemote ?? '' + '\0' + gitCommonDirIdentity)`，无 remote 时退化为 common dir + 元数据指纹。目的是 worktree / symlink / cwd 变化不误判同一仓库。
- 用真实临时仓库测试：同一仓库不同进入路径 → 同 identity；两个不同仓库 → 不同 identity。

**C3. Checkpoint 采集（含内容 blob）**
- 按 §12.2 relevant path 优先级收集：PRE 已脏路径 → tool hint 路径 → POST 新变化路径。
- 每个路径记 `CheckpointPathState`（status / staged / binary / contentHash / mode / blobRef）。
- 对 relevant path 保存 before/after **原始内容**进对象存储（`raw-bytes`）；超大文件跳过并降 `completeness` 为 `partial`。
- 性能按 §44.1：先用 `git status` 拿 changed paths，只用 git blob OID，untracked 才额外 hash，**不做全仓库 hash**。
- `completeness: complete|partial|failed` 必须如实反映缺失，绝不乐观。

**C4. Fixture 仓库与黄金场景**
- `tests/fixtures/`：`clean` / `dirty` / `rename` / `binary` / `drift` / `merge` / `rebase` / `large`（§41）。
- **TECH §62 黄金场景**作为常驻测试：README.md（轮前用户改）→ BASELINE；src/auth.ts（轮内 Agent 改、轮后用户再改）→ DRIFT；tests/auth.test.ts（轮内 Agent 建）→ AGENT；Safety = FORK_ONLY，reason 指向 `src/auth.ts changed after the recorded turn`。以后每个版本都必须通过。

### Phase D — Attribution Engine（TECH §9 / §10，纯函数）

- 三态比较 PRE/POST/CURRENT：`PRE==POST` 无变化；`PRE!=POST && CURRENT==POST` → 候选 AGENT；`PRE!=POST && CURRENT!=POST` → DRIFT。
- Baseline：`PRE(path) != HEAD(path)` ⇒ `baseline=true`，且必须算 `delta(PRE,POST)` 而不是 `delta(HEAD,POST)`（§10.3，这是"支持脏工作区"的关键，也是最重要的差异化）。
- UNCERTAIN 的触发条件按 §10.4 逐条落地（pre/post 缺失、hash 不稳、rename 冲突、binary 无素材、watcher 与 checkpoint 矛盾）。
- `confidence: high|medium|low` 按 §10.5；**`low` 的 AGENT 不得直接等价于 Rewind SAFE**（安全不变量）。
- `FileToolHint` 只做辅助证据，不单独作为真相（§8.1：Agent 可能经 shell / formatter / package manager 间接改文件）。
- 单测矩阵按 §40 全量覆盖（含 baseline 同文件 / 不同文件、create / delete / rename / binary、post-turn 手工编辑、缺失 pre/post）。

### Phase E — Safety Engine（TECH §13–§16，纯函数）

- `evaluateSafety(input: SafetyInput): SafetyVerdict`：无 IO、无 LLM、无全局状态，同输入同输出。
- 规则接口 `{id, evaluate(input): SafetyReason[]}`，聚合 `highestSeverity(reasons)`；`allowedActions` **单独计算**（§15：FORK_ONLY 与 UNPROTECTED 不是单纯的危险度关系）。
- S001–S012 逐条实现，每条都要 positive / negative / reason code / precedence / allowedActions 五类断言。
- FR-11 动作表钉死：SAFE 全开；CAUTION 的 Rewind 默认关闭；FORK_ONLY 无 Rewind；UNPROTECTED 的 Fork 视 checkpoint 而定。**禁止"按钮可点、点完才说危险"**。
- §43 不变量用 property test 钉住：① 目标 current hash ≠ post hash 时不得输出 `SAFE + REWIND`；② 关键 checkpoint 缺失时不得允许 Rewind。
- 缓存策略按 §16：Turn close 时算 initialVerdict；`evaluateSafety` 必须**强制刷新 CURRENT**；UI 显示 `evaluated Xs ago`。

### Phase F — Host API（形态由 A1 结论决定）

- 契约类型放 `src/shared/contracts/`，带 `{ apiVersion: 1, data }` 信封（§49），让版本不匹配显式失败而不是静默错配。
- 查询层：`listTurns`（cursor 分页，§44.3）、`getTurnDetail`、`getDiff`、`evaluateSafety`。
- **若 A1 证明 remote 可用**：host 侧 `TypertRemoteService` + 手写的 remote 描述物，client 侧接入；`client` 不直接读 SQLite（§28 硬约束）。
- **若 A1 证明不可用**：不做假承诺——V0.1 的 Safety/Attribution 结论改由 host 侧本地导出（JSON 报告 / 诊断面板）呈现，`conversation.view` 里的 Safety Badge 明确顺延，并在 README 的兼容矩阵里如实写明。此分支需回报后再定，不擅自扩大改动。

### Phase G — Client UI（依赖 Phase F）

- 现有 `conversation.view` 上增量：文件数 / tests / Safety Badge / reasons / recommended action；Turn Detail（Summary / Changes / Commands / Tests / Evidence / Recovery 占位）。
- diff 按需加载（§44.2）：Timeline 不加载完整 diff，点击 path 才 `getDiff`。
- i18n 沿用现有 `ctx.locale.register(NS, {zh, en})` 机制，新增键；UI 状态区分 LOADING / LIVE / STABLE / STALE / ERROR。
- 不用颜色单独表意（§14.4）；禁止模糊表达（§14.2：不得出现 "probably safe"）。

### Phase H — Hardening 与发布门槛

- **fail-open 认证**：dataDir 不可写、SQLite 损坏/外来库、git 不可用、diff 失败 → Turn 继续、verdict 降为 UNPROTECTED、只记诊断。这条直接对应 PRD §19.2 的四个 0 容忍指标。
- diagnostics 按 FR-11 暴露：插件版本、解析后的数据根、存储占用、启用状态、最近有界错误；**每条消息在 `record` 调用处先过 `redact`**，并有测试证明带假 key 的消息落盘为掩码。
- 性能按 §20：1000 Turn 分页可用；Timeline P95 < 500ms、Turn detail P95 < 300ms、Safety evaluate < 1s。
- 兼容矩阵（§37）：`dev | 0.1.1-rc.2 | legacy development baseline`，未验证的版本不宣称。
- README：install / uninstall、开发命令、数据目录（`$DSH_HOME/turnscope`）、默认保留期（30 天 / 100 MiB）、**如实说明 Restore 与 Fork 未实现**、`External effects are not rewindable by Turnscope`。
- 按 TECH §54 的 Definition of Done 逐条勾选。

## 验证方式

**每个任务**：`pnpm vitest run <该任务的 spec>` → 全绿 → `pnpm typecheck` 退出 0 → 提交。

**每个阶段末**：`pnpm test`（全量，含既有 201 个通过用例不回归）+ `pnpm build`。

**Phase A 结束**：在隔离 `DSH_HOME` 下 `dsh --profile <smoke> --dump-config` 确认 turnscope bundle 行被激活；`npm pack` 产物能被 `dsh plugin --profile <smoke> add ./<tarball>` 装上并 boot 成功。**绝不改动 `~/.dsh/profiles/web`**。

**Phase C/D/E 结束**：黄金场景（TECH §62）必须通过。

**最终安全验收**（TECH §54 + 旧计划 Final Verification 的检查项，按 v0.2 调整）：
1. `grep -rn "reset --hard\|checkout\|write-tree\|hash-object -w\|git tag\|git commit" src/` 无命中（V0.1 零 Git 写）。
2. `grep -rn "exec(\|execSync\|shell: true\|sh -c" src/` 无命中。
3. `grep -rln "node:sqlite" src/` 只命中 `src/host/storage/`。
4. `grep -rn "fetch(\|node:http\|undici" src/` 无命中（永不上传）。
5. `'raw-bytes'` 只出现在 `src/host/git/`。
6. 故意损坏的数据目录（不可写路径 / 外来 SQLite 文件）下，harness 继续运行、插件保持 loaded 但 inert。

## 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 第三方 remote 不可用 | Safety UI 无法进会话视图 | A1 spike 先做；有明确回退（Phase F 第二分支），不阻塞后端 |
| 脏工作区归属错误（v0.2 标的"极高"风险） | 把用户改动误判为 Agent | delta(PRE,POST) + baseline 标记 + §40 全量单测；`low` confidence 不得判 SAFE |
| Schema 迁移改列类型（INTEGER→TEXT 时间戳） | 已有本地数据不可读 | 写真实 001→002 迁移；`~/.dsh/turnscope` 已有数据，迁移前先做只读备份校验 |
| recovery blob 原字节落盘 | secret 落盘 | `0o600` + local-only + 保留期 + 无网络代码守卫 + README 明示 |
| 大仓库性能 | 采集拖慢 Agent | relevant paths only + git OID + untracked 才 hash + lazy diff（§44） |

## 明确不在本轮范围

真正 Rewind 写操作、Worktree 自动创建、Retry 自动建 Session、Compare、大量 Rule Engine、AI 根因分析、Trace export / Repro bundle、非 Git snapshot engine（PRD §15「明确不做」）；以及 V0.2 的 Recovery Planner / journal / crash 恢复与 V0.3 的 Fork / lineage。
