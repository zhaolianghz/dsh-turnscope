## Task 1 / 4 — `turn-model.ts`: switch source from `ConversationSnapshot` to `ChatSnapshot`

**Files**: `src/client/turn-model.ts`.

**Steps**:

1. Replace the top-of-file import:
   ```ts
   // before
   import type { ConversationNode, ConversationSnapshot } from '@deepseek-ai/dsh-client-runtime/client'
   // after
   import type { ConversationNode, ChatSnapshot } from '@deepseek-ai/dsh-client-ui-conversation/client'
   ```
2. Rewrite `deriveTurnModels` signature and body to read from `ChatSnapshot`:
   * Take `chat: ChatSnapshot`.
   * `const turns = chat.legacy.turnTimings` (no `?? new Map()` — the caller
     already substitutes `EMPTY_CHAT_SNAPSHOT` upstream; we still early-return
     `[]` when `turnTimings.size === 0` because that's the "no turns yet"
     signal).
   * Compute `firstRealSeq` over `chat.legacy.nodes` per V0.1.3 rules.
   * Drop `?? []` and `?? new Map()` defaults that V0.1.4 added — they're
     no longer needed because `chat` is typed non-null at this point.
   * Per-turn iteration still renames the per-turn grouped list to `turnNodes`
     to avoid shadowing (kept from V0.1.4).

3. Update the JSDoc on `deriveTurnModels` to mention `ChatSnapshot`.

4. Run `pnpm test tests/client/turn-model.client.spec.ts` and confirm it
   compiles (it will fail at runtime because fixtures are still
   `ConversationSnapshot`-shaped — that's expected; fix in Task 4).

**Self-check**:
- [ ] `pnpm typecheck` fails only on `turn-model.client.spec.ts` / `support.ts`
      fixtures (no other type errors).
- [ ] No regressions in the `node_modules`-installed types
      (`@deepseek-ai/dsh-client-ui-conversation/client` re-exports

## Task 2 / 4 — `TurnscopeView.tsx`: wire `useChat` selection

**Files**: `src/client/TurnscopeView.tsx`.

**Steps**:

1. Remove the V0.1.4 console debug logs (the `useEffect` block printing
   `[V0.1.4 DEBUG]` / `[V0.1.4 VIEW DEBUG]`).
2. Add a `useMemo` import from `react`.
3. Inside the component:
   * `const openState = useSession(s => s.openState);` — unchanged.
   * `const chat = useChat();` — new. Falls back to `EMPTY_CHAT_SNAPSHOT`
     if `chat === undefined` (first-frame mount edge case). Import
     `EMPTY_CHAT_SNAPSHOT` from `@deepseek-ai/dsh-client-ui-conversation/client`.
   * `const turns = useMemo(() => deriveTurnModels(safeChat), [safeChat]);`
     where `safeChat = chat ?? EMPTY_CHAT_SNAPSHOT`.
4. Add `EMPTY_CHAT_SNAPSHOT` and `ChatSnapshot` to the type imports.
5. The rest of the component (rendering `turns`, recovery section, etc.)
   is unchanged.

## Task 3 / 4 — Update test fixtures + spec coverage

**Files**:
- `tests/client/turn-model.client.spec.ts`
- `tests/client/view.client.spec.tsx`
- `tests/client/support.ts`

**Steps**:

1. Drop the V0.1.4 test that fed `undefined` / `{}` to `deriveTurnModels`
   (no longer relevant — the function expects `ChatSnapshot`).
2. In `tests/client/support.ts`:
   * Add `makeChatSnapshotFixture(turns: Array<{...}>)` building a
     `ChatSnapshot` literal with the needed `legacy.turnTimings` /
     `legacy.turnEnds` / `legacy.nodes` / `order` shape. Don't over-build —
     only the fields `deriveTurnModels` reads.
   * Drop the legacy `ConversationSnapshot`-shaped builder.
3. Rewrite the `turn-model.client.spec.ts` cases around the new helper:
   * Empty `turnTimings` ⇒ `[]`.
   * Single completed turn with one user + one assistant node.
   * Single running turn (`turnTimings.get(t).endTime === undefined`,
     `turnEnds.has(t) === false`) ⇒ status `running`.
   * Multi-turn, ordering = insertion order of `turnTimings`.
   * Bootstrap-context drop (V0.1.3 case): turn with a `kind: 'context'`
     node whose seq is less than the first user/assistant seq must be
     dropped.
   * First real seq missing (no `user`/`assistant`) ⇒ all nodes kept
     (V0.1.3 fallback).
4. In `view.client.spec.tsx`:
   * Render harness now provides a `useChat` selector hook returning a
     fixture chat snapshot; keep `useSession` returning the same minimal
     `SessionSnapshot`-shaped object (openState etc.).
   * Existing assertions on empty-state and "show turn list when chat has
     turns" stay green.
