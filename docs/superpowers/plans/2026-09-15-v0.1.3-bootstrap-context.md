# V0.1.3 — Drop Session-Bootstrap Context Nodes

Implementation plan for `docs/superpowers/specs/2026-09-15-v0.1.3-bootstrap-context.md`.

Three bite-sized tasks.

## Task 1 — Bootstrap-context filter

**File**: `src/client/turn-model.ts`

- In `deriveTurnModels`, before the per-node grouping loop, compute
  `firstRealSeq` as the minimum `seq` across all nodes with
  `kind === 'user'` or `kind === 'assistant'`, or `undefined` if there
  are none.
- In the grouping loop, when `node.kind === 'context'` and
  `firstRealSeq !== undefined` and `node.seq < firstRealSeq`, `continue`
  (skip the node, do not push it onto the per-turn group).
- Leave every other node kind alone. The filter is conservative:
  pre-first-prompt `context` only.

**Verify**: `pnpm typecheck` clean.

## Task 2 — Tests for the bootstrap filter

**File**: `tests/client/turn-model.client.spec.ts`

Three new tests, all using the existing `snapshotWith` / `node` helpers:

1. **`drops context nodes whose seq is before the first user/assistant node`** —
   snapshot has two `context` nodes at `seq = 1, 2`, then a `user` at
   `seq = 5`, then a `turn-end` at `seq = 10`. Assert turn 1's activities
   contain only the user message (no `Context` entries) and the
   `activityCount` is 1.
2. **`keeps context nodes that arrive after the first user/assistant node`** —
   context at `seq = 4`, user at `seq = 5`, assistant at `seq = 6`,
   `turn-end` at `seq = 10`. Assert turn 1's activities include both
   context and user/assistant in their original order.
3. **`keeps all context nodes when no user or assistant message exists yet`** —
   snapshot has only `context` nodes, no user/assistant. Assert the
   activities are preserved (the renderer should not silently eat a
   pre-prompt context burst in a fresh session).

**Verify**: `pnpm test tests/client` green; test count +3.
