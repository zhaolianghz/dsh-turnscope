# V0.2 Safe Rewind Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver PRD §16 / FR-12 / FR-13: a real, byte-correct Safe Rewind for Git workspaces where the turn's evidence is complete and the workspace has not drifted since preview.

**Architecture:** Preview-then-Apply with a state-hash guard. A pure-function `planner.ts` derives a `RecoveryPlan` from the stored `TurnChangeSet` + pre/post/current checkpoints; a side-effect `runner/` writes via `fs.rename` (never `git reset` / `checkout`); a journal records every step so a crashed apply can be detected on next boot and offered for inspection. New migration `003_recovery.sql` adds `recovery_plans` / `recovery_journal`. Two new RPC methods (`previewRewind` / `applyRewind`) reuse the V0.1 Remote channel. Architecture guard expansion forbids `node:child_process` inside `host/recovery/`.

**Tech Stack:** TypeScript 6 / ESM / Node 22.19+ / Vitest 4 / `node:sqlite` (via `better-sqlite3` from V0.1) / pnpm 11.7 / V0.1 `host/diff/unified.ts` Myers engine / V0.1 `host/storage/object-store.ts` (RECOVERY_BLOB).

**Spec:** `docs/superpowers/specs/2026-09-11-v0.2-v0.3-recovery-design.md`. Every decision, type, schema, and test below is bound to a specific section in that spec; do not invent field names or methods.
